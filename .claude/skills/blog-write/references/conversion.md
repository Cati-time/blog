# 변환기가 하는 일 — `npm run import`

`scripts/import-doc.mjs` 가 정본이다. 이 문서는 그 동작을 설명한다. 둘이 다르면 스크립트가 맞고, 이 문서를 고친다.

## 1. 바꾸는 것 (모양)

| 대상 | 처리 |
| --- | --- |
| `style` · `class` · `id` 등 속성 | 지운다. 남기는 속성은 링크 `href`, 이미지 `src` `alt`, 표 `colspan` `rowspan`, 목록 `start`, 체크박스 `checked` 뿐 |
| `<font>` `<span>` `<center>` | 껍데기만 벗기고 안의 글자는 그대로 둔다 |
| 스타일로만 된 굵게·기울임·취소선 | `font-weight:700` → 굵게, `font-style:italic` → 기울임, `line-through` → 취소선 표기로 **살린다**. 색·글꼴·크기·배경색은 버린다 |
| 구글 문서의 `<b style="font-weight:normal">` 전체 감싸기 | 굵게가 아니므로 벗긴다 |
| HTML → Markdown | 문단, 제목, 목록, 링크, 굵게·기울임, 인용, 코드 블록(언어 유지), 단순 표, 이미지, 체크리스트 |
| 코드 언어 이름 | 소문자로 (`TypeScript` → `typescript`, 색 입히기용) |
| 첫 `#` 제목 | 문서 맨 앞에 있으면 frontmatter `title` 로 옮긴다 |
| 본문에 남은 `#` | 모든 제목을 한 단계 내린다 (`#` → `##` …). 블로그 본문은 `##` 부터라서 |
| 한글 조사와 붙은 강조 | `**"인용"**은` 처럼 강조가 풀리는 위치만 `<strong>` 태그로 쓴다 |
| 이미지 | 원본 옆 파일과 내장(data URI) 이미지를 글 폴더로 복사하고 **마크다운 이미지** `![설명](./파일명)` 으로 쓴다. HTML `<img>` 로 두면 블로그가 파일을 배포하지 않아 깨진다 |
| 이미지를 감싼 원본 파일 링크 | 링크만 푼다 (블로그에서는 열리지 않는 경로라서). 이미지는 그대로 |
| `<figure>` · `<figcaption>` | 이미지는 마크다운 이미지로, 캡션은 바로 아래 문단으로. 캡션 글자는 그대로 |
| 속성 없는 `<p>` · `<div>` (Markdown 원본) | 껍데기라서 벗기고 일반 문단으로. 안의 마크다운이 살아난다 |
| 원본 frontmatter (Markdown) | 블로그 형식으로 바꾼다. `title` `description` `date` `tags` 만 가져온다 |

## 2. 그대로 두는 것

- **모든 글자와 문장부호, 순서.** 맞춤법·띄어쓰기·어투도.
- 코드 블록 안의 모든 것 (코드 안의 `<span style>` 같은 예시도).
- 마크다운으로 표현할 수 없는 구조는 **정리된 HTML** 로 유지한다: 병합 셀 표, `<details>`/`<summary>` 접기, `<kbd>` `<sub>` `<sup>` `<mark>` `<abbr>` `<u>`.
  - 이 HTML 블록 안에 이미지가 있으면 표시되지 않는다. 보고서 `참고` 줄과 검사 **P5** 가 알려 주며, 이미지를 블록 밖으로 빼야 한다.
- 외부 이미지 주소 (내려받지 않는다 — 보고서에 "외부 링크" 로 센다).
- 사설 IP·이메일·사내 주소 같은 글자 (검사기가 경고하고, 공개 여부는 사람이 정한다).

## 3. 빼는 것 (내용이 아니거나 공개 블로그에서 쓸 수 없는 것)

`<script>` `<style>` `<noscript>` `<template>` `<iframe>` `<object>` `<embed>` `<form>` `<button>` `<select>` `<textarea>` `<link>` `<meta>` `<base>` `<canvas>` `<svg>` `<video>` `<audio>`, 체크박스가 아닌 `<input>`, `javascript:` 링크.

뺀 것은 보고서 `뺀 요소` 에 태그별 개수로 나온다. `<svg>` `<video>` `<audio>` `<canvas>` 는 내용일 수 있어 "이미지 파일로 넣어 달라" 는 안내가 함께 나온다.

## 4. 본문 대조는 어떻게 하나

원본 본문(뺀 요소와 제목으로 옮긴 첫 `#` 을 제외)과 변환 결과에서 **글자·숫자·문장부호(`.,?!:;%`)만 뽑아 순서대로 이어 붙인 문자열**이 완전히 같아야 ✔ 다.

- 공백·줄바꿈·마크다운 기호(`*` `#` `|` `-` 등)·HTML 태그는 비교하지 않는다 — 모양이라서.
- 한 글자라도 바뀌거나 빠지거나 더해지면 ✖ 와 함께 처음 다른 곳 앞뒤 15자를 보여 준다.
- 이미지 설명(alt)과 링크 주소는 본문 글자가 아니라서 비교하지 않는다.

## 5. 변환기가 못 하는 것

| 상황 | 대처 |
| --- | --- |
| `.docx` · PDF · 구글 문서 링크 | HTML 이나 Markdown 으로 내보내서 다시 |
| 원본 폴더의 다른 문서로 가는 링크 (노션 하위 페이지 등) | 보고서 `⚠ 링크` 로 알린다. 공개 주소로 바꿀지, 링크만 풀지 사용자가 정한다 |
| 노션 콜아웃·토글 같은 전용 블록 | 글자는 옮기지만 모양은 일반 문단이나 `<details>` 접기가 된다 |
| 수식(LaTeX), 다이어그램(mermaid 코드 제외), 임베드 영상 | 블로그가 지원하지 않는다. 이미지로 넣거나 링크로 |
| 옵시디언 `[[위키 링크]]` · `![[이미지]]` | 글자 그대로 옮긴다. 블로그에서는 링크가 되지 않으니 사용자와 정한다 |

## 6. 블로그에 허용된 HTML (검사기 기준)

| 구분 | 태그·속성 |
| --- | --- |
| ✅ | `details` `summary` `kbd` `sub` `sup` `mark` `abbr` `u` `br`, 병합 셀 `table` |
| ⚠ 무의미 | `class` · `id` (본문용 스타일이 없다) |
| ✖ 빌드 실패 | 글 폴더 이미지를 HTML `<img>` 로 쓰기(P5 — `![설명](./파일)` 로), `style` 속성, `script` `iframe` `style` `form` `object` `embed` `link` `meta` `base` 태그, `on…=` 이벤트, `javascript:` 링크 |

블로그는 쓴 문장부호를 **그대로** 보여 준다. `--force` 가 `–force` 로, `"따옴표"` 가 `“따옴표”` 로 바뀌는 자동 변환은 꺼 두었다 (`astro.config.mjs`).
