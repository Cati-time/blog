# blog-wording — 개발자가 쓰는 말로

이 스킬의 약속은 셋이다.

1. **근거 없는 대체어를 지어내지 않는다.** 바꿀 말은 용어집에 있는 것만 — 사용자 결정이거나, 한국어 기술 블로그에서 실제로 센 말.
2. **사용자 결정이 근거보다 우선한다.** 실측이 달라도 사용자가 정한 말을 쓴다. 다만 실측이 어긋나는 쓰임은 사용자에게 보여 준다.
3. **용어 · 말투만 고친다.** 숫자 · 사실 · 판단 + 단서 문장은 그대로. 고칠 문장은 사용자 확인 뒤 반영한다.

| 무엇 | 정본 |
| --- | --- |
| 용어집(안 쓰는 말 · 쓰는 말 · 근거 · 결정) | `scripts/check-wording.mjs` 의 `TERMS` — 표로 보기: `npm run check:wording -- --list` |
| 말투 규칙(규칙형 «~한다» · 억지 피동) | 같은 파일의 `PLAIN_END` · `FORCED_PASSIVE` |
| 실측 원천 · 수집물 · 집계표 | 저장소 **밖** 노트 폴더 `../blog-notes/style/` (수집물은 공개 금지) |

## 용어집의 결정 세 가지

| decided | 뜻 | 검사 출력 |
| --- | --- | --- |
| `user` | 사용자가 정한 말 (예: grow → 확장한다 · 발전시킨다, 정본 → 단일 진실 원천(SSOT), 반송 → 반려, 헌법 → 규칙, 도우미 → 헬퍼, 코드가 주어인 «소유» → 상태를 관리한다) | 바꿀 말을 그대로 제안 |
| `evidence` | 원천에 그 말이 거의 없고 대체어가 많이 나온다 | 바꿀 말을 제안 |
| `ask` | 원천 차이가 작거나 팀 용어다 — 바꿀지 · 무엇으로 바꿀지는 사용자가 정한다 | «(사용자 확인)» 을 붙여 후보만 |

검사는 **경고만** 낸다. 정규식은 문맥을 모른다 — 장소 뜻의 «자리», 사람에게 쓴 «키우다», «기대하다»(expect) 같은 오탐은 사람이 거른다.

## 절차

1. **검사** — `npm run check:wording [slug …]`. 줄 번호 · 규칙 id · 걸린 말 · 바꿀 말이 나온다.
2. **후보 목록** — 문맥을 보고 오탐을 뺀 뒤, 문장마다 «줄 · 지금 문장 · 바꾼 문장 · 규칙 id · 근거» 표를 만든다.
   - 바꾼 문장은 걸린 말만 바꾼다. 문장을 새로 쓰지 않는다. 조사(은/는 · 이/가 · 을/를 · 으로/로)는 바뀐 말에 맞춘다.
   - «단일 진실 원천(SSOT)» 처럼 «처음 한 번 풀어 쓰는» 말은 글마다 첫 등장에만 풀어 쓴다.
   - `ask` 항목은 바꾼 문장 대신 후보 말과 근거만 적는다.
   - 인용문: 사람이 실제로 한 말은 그대로 두고, 규칙 문서를 옮긴 인용은 결정된 용어로 바꾼다. 그대로 둔 줄은 줄 끝(또는 바로 윗줄)에 `<!-- wording-ok -->` 를 달아 검사에서 뺀다.
   - 억지 피동 · 규칙형 «~한다» 는 «선택 항목» 표로 따로 — 기본은 «그대로», 문장마다 확인받는다.
   - 글 제목이 걸리면 근거 단어로 안을 2~3개 낸다. slug 는 그대로, 시리즈 상자 · frontmatter 를 함께 고친다. 제목에서는 «처음 한 번 풀어 쓰기» 를 하지 않고 짧은 말(예: SSOT)을 쓴다 — 본문의 첫 등장에서 풀어 쓴다.
   - 같은 말이 한 글에 여러 번이면 한 줄로 묶고 줄 번호를 나열한다.
3. **사용자 확인** — 표를 보여 주고 문장마다 받는다(전부 · 일부 · 안 함). 다른 세션이 같은 글을 고치고 있으면 누가 반영할지 먼저 정한다.
4. **반영** — 확인받은 문장만 고친다. 같은 말을 글 전체에서 바꿀 때는 뜻이 같은 곳만.
5. **검증** — `npm run check:wording <slug>` 로 줄었는지, `npm run build` 통과. 커밋은 `edit:` (본문) · `chore:` (용어집 · 스킬).

## 용어집 고치기

- 사용자가 새 말을 짚으면(«이 말 안 써»): `TERMS` 에 `decided: 'user'` 로 넣고, 원천 실측을 세어 `evidence` 칸을 채운다.
- 실측으로 넣을 때: 안 쓰는 말과 대체어를 **같은 원천에서** 센다. 대체어가 원천에 거의 없으면 넣지 않고 `ask` 로 둔다.
- 원천은 한국어 기술 블로그 본문(회사 · 개인). 수집할 때 robots.txt 를 지키고 요청 사이를 띄운다. 문장을 옮겨 적지 않고 말의 횟수만 센다. 수집물은 저장소에 넣지 않는다.
- 이 파일과 `WRITING_GUIDE.md` 의 용어 절은 같은 커밋에서 고친다.

## blog-compose 와의 연결

blog-compose 의 «발행» 1단계(윤문) 앞에서 이 스킬의 1~4 를 돈다. 순서: **용어(이 스킬) → 윤문(humanize-korean, 선택) → 발행**.

## 하지 않는 일

- 용어집에 없는 대체어 제안, 문장 새로 쓰기
- 사용자 확인 없이 본문 일괄 치환
- 숫자 · 사실 · 인용 바꾸기
- 수집한 원천 문장을 저장소 · 글에 옮기기
