# blog-compose — 메시지 · 표 양식

꺾쇠(`<…>`)는 채울 자리다. 메시지는 원천 세션의 **id** 로 보낸다.

## §1 뼈대 · 조사 요청 (블로그 → 원천)

```
[blog 세션 → <원천 세션 제목>] <글 · 시리즈 이름> — 뼈대 + 조사 요청 (4단계 중 ①)

## 사용자 방향 (<날짜>)
- <사용자가 한 말 원문 또는 요지>
- 독자 · 말투 · 원칙: <일반 개발자 · 필자 1인칭 · «왜» 중심 · 숫자는 실측만, 실측 없는 효과는 «판단 + 단서» · 시점은 상대 표현>
- 공개 글에는 저장소 이름 · ADR 번호 · 해시 · 사람 이름을 쓰지 않는다(답에는 자유롭게).

## 뼈대와 섹션별 요청
1. <섹션> — <보여 줄 것>. 필요한 것: <값 · 정의 · 근거>
2. …

## 함께 묻고 싶은 것
- <«왜» 질문 · 되돌린 시도 · 반례>

이번 회신은 섹션별 조사 답이면 됩니다. 섹션마다 값 · 정의 · 근거(파일:줄 · 커밋 · 명령) · 기준 ref＠sha 를 적어 주세요.
숫자는 메모 값을 보지 말고 직접 세어 주세요. 회신은 이 세션(<블로그 세션 id>)으로.
```

## §2 사실 확인 요청 (블로그 → 원천)

```
[blog 세션 → <원천 세션 제목>] <글> 사실 확인 요청 (R<n> · 범위: 재확인|추가 · 발단: 계획|사용자 지적)

## 읽을 것 (blog 저장소 · 읽기 전용)
- 본문: git -C <blog 저장소> show <sha>:<글 경로>
- 지난 회차 뒤 바뀐 곳: git -C <blog 저장소> diff <앞 sha>..<sha> -- <글 폴더>  (줄: …)
- 이번에는 바뀐 곳만 봐 주세요(첫 회차면 전체).

## 확인할 주장 (번호로 답해 주세요)
A1. <주장 요지 · 확인할 값 · 세는 방법이 있으면>
B1. …

## 답 형식
- §3 표 한 장. 숫자는 제 값을 보지 말고 직접 세어, 세는 명령을 근거 칸에 적어 주세요.
- 개인정보 예시 문자열은 인용하지 않습니다.
- 회신은 이 세션(<블로그 세션 id>)으로.
```

## §3 사실 확인 표 (원천 → 블로그)

머리: `[사실 확인 R<n>] <글 경로>＠<sha>` · `범위: 재확인 | 추가` · `발단: 계획 | 사용자 지적` · (있으면) `제외: <커밋> <사유>`

- **범위**: 새 글의 첫 회차와 새로 쓴 부분은 `추가`, 앞 회차에서 고친 줄만 다시 보는 회차는 `재확인`. 첫 회차를 `재확인` 으로 적으면 «오류 0 까지 몇 회차» 를 셀 수 없다.
- **제외**: 뜻이 바뀌지 않는 편집(윤문 · 쉼표)을 확인 대상에서 뺐으면 머리에 `제외: <커밋> 쉼표만` 처럼 적는다.

| # | 주장 | 판정 | 고침 부류 | 근거 | 측정 | 불일치 원인 | 효과 주장 | 기준 판 | 정의 | 출처 |
|---|---|---|---|---|---|---|---|---|---|---|
| A1 | <한 줄 요지> | 그대로 · 고침 · 뺌 | 수치 · 이름 · 범위 · 인과 · 시간-달력→작업 · 시간-기타 · 근거 없음 | 파일:줄＠sha · 커밋 · 명령 · 없음 | 단독 · 이중-일치 · 이중-±3 · 이중-불일치 | (이중-불일치일 때) 범위 · 정의 · 시점 · 출처 없음 · 재현 안 됨 · 확인 범위 밖 | 아님 · 실측 · 판단+단서 | <셈한 원천 sha 또는 날짜> | <무엇을 · 어디까지 세었나> | 조사 회신 · 직접 셈 |

- **기준 판 · 정의 · 출처** 세 칸은 선택이지만 채우면 셈이 정확해진다. 두 측정의 판이나 정의가 다르면 `≠` 를 쓰거나 공백을 둔 ` / ` 로 둘 다 적는다(예: `00dd54e03 / ae9715e5a`). 원인 칸이 비어 있어도 판 · 정의가 다르면 그것이 불일치 원인 후보다.
- **출처** = 그 값이 조사 회신에서 왔는지(`조사 회신`), 확인하는 쪽이 직접 셌는지(`직접 셈`). 조사 회신에서 온 값이 얼마나 고쳐졌는지가 따로 집계된다.

- 집계 줄은 쓰지 않는다 — 표에서 계산한다(손으로 쓴 집계가 자주 틀렸다).
- 칸 안 명령의 파이프는 `\|` 로 쓴다.
- 앞 회차 판정이 재대조로 바뀌면 다음 회신 맨 앞에 고정 꼴로 싣는다:
  `R<n> 정정: <#> 판정 <앞>→<뒤> · 측정 <앞>→<뒤> · 근거 <…>`

## §4 저장소 밖 기록 · 커밋 메시지

기록 파일: `../blog-notes/fact-checks/<slug>-R<n>.md`

```
# [사실 확인 R<n>] <글 경로>＠<sha>
- 확인한 세션 · 날짜 · 기준 ref＠sha · 범위 · 발단

## 받은 표 (원문 그대로)
…

## blog 처리
| # | blog 가 다시 센 값 | 처리 |
|---|---|---|
| … | … | 반영 · 원래 값 유지(재대조) · 되물음 |
```

커밋 메시지는 공개된다 — 집계만 쓴다:

```
edit: <글> — 사실 확인 R<n> 반영 (초안)

사실 확인 R<n>(<글>＠<sha>): 주장 N · 그대로 a · 고침 b · 뺌 c · 이중 측정 d(일치 · ±3 · 불일치).
다시 센 뒤 x건 반영, y건은 재대조로 원래 값 유지. 표 원본은 공개 저장소 밖 노트에 둔다.
- <고친 것 요지 — 내부 경로 · 해시 · ADR 번호 없이>
```
