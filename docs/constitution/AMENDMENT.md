# 헌법 개정 절차 — blog

> 이 헌법은 canon 판 **0.44.0** 의 인스턴스다 · web-kind **0.1.0** · 틀: harness `canon/` · 개정 수신: 이 문서 §5.
> 이 문서는 헌법을 **무엇으로 두고 어떻게 바꾸는지** 를 정한다. 절차는 여기에만 있다 — `RULES.md` · `WORKFLOW.md` 에 옮겨 적지 않는다.

## 1. 헌법의 구성

| 문서 | 다스리는 것 |
| --- | --- |
| `docs/constitution/RULES.md` | 코드와 글이 따라야 하는 규범 — 몸통(현재 · 지향 · 간극) · 글 규칙(`R-BLOG-*`) · 바깥 접점 · 거버넌스 |
| `docs/constitution/WORKFLOW.md` | 일하는 흐름의 규범 — 흐름 층 · 루트 플로우 «글 한 편» · Subflow 계약 · 레인 선 · 감독 절 |
| `docs/constitution/AMENDMENT.md` | 이 절차 |
| `docs/constitution/CHANGELOG.md` | 변경 색인(ADR 한 줄씩) |
| `docs/adr/constitution/` · `docs/adr/workflow/` | 결정 기록 — RULES · AMENDMENT / WORKFLOW |
| `docs/adr/TEMPLATE.md` | ADR 필수 구조 |

- **축을 섞지 않는다** — RULES 에 흐름을, WORKFLOW 에 코드 규칙을 넣지 않는다.
- 통합형이다(플로우 하나). 플로우가 둘 이상 생기거나 WORKFLOW 에 한 플로우 고유의 방법이 쌓이면 `workflow/rootflow/` 로 나눈다 — 판정: «다른 플로우로 바꿔도 이 문장이 그대로 참인가».
- **안내 문서는 헌법이 아니다**: `WRITING_GUIDE.md`(팀원용 글쓰기 안내) · `docs/claude-management.md`(설정 · 절차 안내) · `docs/design-tokens.md`(토큰 정의서) · 스킬 넷(`.claude/skills/blog-*`). 이 문서들은 헌법을 **가리키고**, 헌법과 겹치는 MUST 를 따로 갖지 않는다. 겹치면 헌법이 이긴다.

## 2. 조문 쓰는 기준 (MUST)

1. **조문은 판정의 근거를 말하고 사례를 열거하지 않는다.** 예시는 예시로 표시한다.
2. **조문마다 집행 한 줄** — 가드 · 빌드 검사 · 리뷰 중 무엇이 지키는지, 어긋나면 무엇이 일어나는지(`RULES.md` §조문 꼴).
3. **구체는 소유한 곳이 갖는다** — 다른 문서 · 설정이 가진 값(분류 목록 · 토큰 값 · 파일 수)을 옮겨 적지 않고 가리킨다. 숫자를 적으면 셈 명령 · 기준 ref 를 함께 적는다.
4. **관찰 근거 없는 문장은 «지향» 에만 쓰고 출처를 단다**(사용자 결정 · ADR).

## 3. 제 · 개정 절차 (MUST)

헌법은 **단독 편집하지 않는다.**

0. **소유 확인** — 세우기 전에 그 축을 이미 다스리는 조문이 있는지 찾는다. 있으면 새로 세우지 않고 그 조문의 집행을 보강한다.
1. **제안** — 무엇을 왜 바꾸나.
2. **토론** — 사용자와 합의. 합의 없이 지우거나 다시 쓰지 않는다.
3. **기록** — ADR 을 `docs/adr/TEMPLATE.md` 구조(Context · 논의된 대안 · 토론 히스토리 · Decision · Consequences)로 남긴다. 자리: RULES · AMENDMENT 변경 = `docs/adr/constitution/` · WORKFLOW 변경 = `docs/adr/workflow/`. 파일 이름 `ADR-NNNN-<슬러그>.md`, 번호는 `docs/adr/**` 를 한 공간으로 보는 레포 순번이다(폴더마다 따로 세지 않는다 — 같은 번호가 둘 생기면 가리킴이 흐려진다 · 법제처 T-002764). 만들기 직전에 `ls docs/adr/*/` 로 다시 세어 집고, harness 에는 착수 알림으로 등록하고, 본문 H1 에 자기 번호를 적는다. 빈 절 · 사후 창작 금지 — 채울 근거가 없으면 먼저 토론한다.
4. **색인** — `CHANGELOG.md` 에 ADR 링크 한 줄.
5. **반영** — RULES · WORKFLOW 를 고친다. 같은 변경에서 그 문서를 가리키는 안내 문서 · 스킬의 문장도 맞춘다.
6. **지침 동기화** — 에이전트 동작이 바뀌면 `AGENTS.md` 를 고친다. **`CLAUDE.md` 는 `AGENTS.md` 의 심링크다(미러 규칙)** — 따로 고치지 않는다. 심링크가 깨지면 그것이 결함이다.
7. **착지** — 레인 가지 → 로컬 CI 초록 → 통합선 `main-cicd`. `main` 머지 · push(= 공개 배포)는 사용자.

- **예외**: 정책이 아닌 순수 정정(깨진 링크 · 경로 · 오타)은 토론 없이 같은 변경에 반영할 수 있다. CHANGELOG 한 줄은 남긴다.
- **심사**: 새 조문 · 칸 매핑이 바뀌는 개정은 harness 법제처 심사를 민원과 경유로 받는다(`Harness-Notify: review` 트레일러).

## 4. 판 표지

- 이 문서 · `RULES.md` · `WORKFLOW.md` 머리에 «canon 0.44.0 · web-kind 0.1.0» 판 줄을 둔다. `AGENTS.md` 머리는 그 줄을 가리킨다.
- 판 줄은 «기준선» 이 harness 장부에 있을 때만 판 올림 분모를 줄일 수 있다 — 표지만으로 면제받지 않는다(canon C246).

## 5. 개정 수신 — 공통 규칙의 새 판을 받을 때 (canon 칸 14 · 칸 18)

1. **수령** — harness 의 «상위 헌법 판 올림 보급» 티켓을 감독(서기 전에는 이 저장소 세션)이 받는다 · 이해 세 줄.
2. **넘김** — 감독은 직접 고치지 않고 상설 헌법 개정 레인(`docs/constitution` 가지)에 넘긴다. 할지 · 언제를 사용자에게 묻지 않는다.
3. **대조** — 분모 행마다 «있다 · 일부 · 없다 · 해당 없음 + 까닭». 지금 구현한 판 → 최신 판을 **한 번에**. 기준선이 없으면 분모 = 설치 분모 표 전수.
4. **개정** — 일부 · 없다를 §3 절차로. 문면 물음은 사용자 말고 harness 티켓으로.
5. **착지 · 보고** — 통합선 초록 착지 · 판 줄과 `AGENTS.md` 포인터를 같은 착지에 · 적용 보고 → 보급과 감수.
- 설치 · 판 올림의 단계는 canon 칸 18 `wf.install`(설치 flow)을 따른다.
